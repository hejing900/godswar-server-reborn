# 客户端里的 `Lv200` 遗留任务副本（2026-10-06）

起因：在服务端看到了 `[Lv200]初入斯巴达`，但新手主线明明是 `[Lv1]初入斯巴达`。

## 1. 它们是两条不同的任务

| | quest **0** | quest **518** |
| --- | --- | --- |
| 中文名 | `[Lv200]初入斯巴达` | `[Lv1]初入斯巴达` |
| **英文名** | **Welcome to Sparta!** | **New to Sparta** |
| Color | **2** | 0 |
| MinLevel / MaxLevel | **200 / 200** | 1 / 120 |
| 发放 → 接手 | Sparta_094 → **Sparta_094（自己）** | Sparta_094 → **Sparta_106** |
| CreatureMapID | 0 | （空） |

英文名不同、Color 不同、接手 NPC 不同——不是同一条任务的重复行，而是**两套并存的任务**。
`0, 1, 2, 9…14` 那一套的接管者都等于发放者（自环、无交接），`518…552` 那一套
每一条的接手 NPC 就是下一条的发放者（真实链式交接）。

标题里的 `[LvN]` 前缀就是该任务的 `MinLevel`（抽样 20 条全部一致），
所以 `200/200` 的任务在界面上就显示成 `[Lv200]…`。

## 2. 参考服从不发放这一套（决定性证据）

拿参考服自己的 S2C `10077`（每个 NPC 的「我会发哪些任务」表）逐条比对。
库里共 353 个不同任务出现在过这些表里：

| 等级形态 | 客户端条数 | 参考服表里出现过 |
| --- | --- | --- |
| **200/200** | **230** | **0** |
| min > max | 136 | 52 |
| 正常 | 810 | 301 |

「0 条」不是因为没机会出现：230 条里 **105 条的发放 NPC 正是被我们抓到过 10077 表的
88 个 NPC 之一**，而那些 NPC 的普通任务在同一张表里大量出现。**105 条机会里 0 条被列出。**

同时 `min > max` 那一类（136 条）有 52 条确实被列出，说明这**不是**「等级写错就丢」的通用规则，
`200/200` 是它自己一类。

## 3. 我们的错

`StarterQuestChain` 把这 230 条**全收了**（斯巴达 115 + 雅典 115），
因为生成器的判据是「Quest.xml 里 NPC 发放的任务」，而这一套每一条都有真实 NPC 发放者。
它们在链里按 `MinLevel=200` 排序，全被排到各自阵营的最后，所以玩家会在推进到后面时突然看到
一堆 `[Lv200]…`（`初入斯巴达`、`探访村长`、`捕蛇新手`…）。

## 4. 修复

`tools/gen_sparta_quest_chain.py` 增加一条跳过规则（`UNREACHABLE_LEVEL = 200`）：
`MinLevel == MaxLevel == 200` 的任务不进化石链。`min > max` 那一类**不跳过**（参考服确实在用）。

| 项 | 修复前 | 修复后 |
| --- | --- | --- |
| 链行数 | 930 | **700**（斯巴达 349 + 雅典 351） |
| 有击杀目标的任务 | 405 | **313** |
| 无 monster id 的目标 | 244,478,479,1221,1482,1483,1557,1561 | 244,1221,1557,1561 |
| 目标缺客户端怪的地图 | 0,2,4,5,6,8,9,11,15,17,210（40 个目标） | 0,5,6,8,9,11,15,17,210（21 个目标） |

覆盖账现在正好平：

```
1176（Quest.xml 总条数）
- 230（200/200 遗留副本）
- 246（GiverName=QuestScroll，物品触发）
= 700 ← 链行数
```

也就是说：**除了物品触发那 246 条，客户端里所有「NPC 发放且不是遗留副本」的任务都已经在链里。**

## 5. 我自己前面判断错了一次

第一次尝试这个过滤时，我看到被删掉的 id 里有 `0,1,2,3,4,5,9…`，误以为删掉的是核心新手内容，
于是把过滤撤了——实际那批正是这套遗留副本。证据是这次补上的
「105 条有机会、0 条被列出」。记录在这里，避免以后再按「id 小就是重要」来判断。

`200/200` 在客户端里被大量使用（230 条）也曾经误导我，但关键不是它常不常见，
而是**参考服对这些条目的处理**：一条都不发。
