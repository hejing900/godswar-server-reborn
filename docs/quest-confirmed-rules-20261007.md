# 用户确认的任务分类与发布规则（2026-10-07）

最新规则已更新为 [独立主线、每日主线与功能任务规则](quest-independent-mainlines-20261007.md)：573～580为独立串行主线，371～382为带120/125级门槛的串行主线，581～626为精确等级发布的独立每日主线，指定功能任务为最低等级发布的一次性任务。**下文记录此前部署版本，不代表当前最新分类或实现。**

本规则取代此前根据 `UIQuestSort`、`Color=0` 和等级分段推断主线的方案。
任务编号、等级、NPC、原始奖励仍取自客户端数据；分类和前置关系按照用户确认的五张表确定。

| 用户确认的表 | 斯巴达编号 | 雅典编号 | 服务端分类 |
|---|---|---|---|
| 第一表，44 组 | 518–565，排除 535、536、557、558 | 对应编号 +1000 | 主线，一次性 |
| 第二表，32 组 | 69–100 | 对应编号 +1000 | 每日 |
| 第三表，12 组 | 342–353 | 对应编号 +1000 | 每日 |
| 第四表，12 组 | 371–382 | 对应编号 +1000 | 每日 |
| 第五表，54 组 | 573–626 | 对应编号 +1000 | 每日 |

主线同时检查人物最低等级和前置任务是否已交付，接取前置任务本身不会解锁后续。
518 没有前置，正常顺序按第一表推进。552–556 是五个 31 级分支，前置均为 551（30 级）；559（32 级）的前置也为 551。
因此完成 551 后，人物达到 31 级可以独立接取五个分支，达到 32 级可以接取 559，不需要完成分支。
559 之后仍按 560 → 561 → … → 565 推进。雅典对应编号全部 +1000。
自动弹出的后续任务优先选择正常主线，未完成的分支不会把后续提示拉回 31 级。

第二至第五表总计 110 组每日任务，相互独立，不检查主线进度。其余非主线任务中 `Color=2` 的同样归为每日。
每日任务每个任务日完成一次。原有每日、公会任务继续按每日计数；其他未改为每日的重复任务保留原有每天三次限制。
其他一次性支线完成后不再发布。通缉、晋升骑士、职业等任务恢复到任务目录，不再因旧排除名单而被丢弃。

所有非主线任务，包括每日和普通支线，发布和接取均使用：

`任务最低等级 - 5 ≤ 人物等级 ≤ 任务最低等级 + 9`

例如 50 级任务在人物 45–59 级时发布；44 和 60 级不发布。旧 `MaxLevel` 保留为原始数据，不叠加成额外发布限制。
主线不使用此窗口，只要求达到任务最低等级并完成前置。
已经接取的任务不会因为升级超出发布窗口而被删除，也不会重新发布。

任务查询、NPC 菜单和实际接取共用同一组等级、阵营、前置、持有状态与每日次数判断。
只有正在持有且满足目标、每日次数未耗尽的任务可以交付；未接取或已交付的任务不能直接领奖。
跨地图的交付 NPC 从其客户端记录的地图读取实际发布身份；地图上的任务标记仍只发给当前地图的 NPC。
卷轴任务保留在目录中，`Color=2` 分类规则同样适用，但当前 NPC 接取流程不提供卷轴入口。

任务日沿用已有服务器本地时间中午 12:00 刷新规则。当日完成次数存入 `character_quest_daily`，人物装备、背包等资料刷新时保留次数。
重接每日任务时，正在持有的存档优先于历史完成记录，避免同一任务编号重复写入。

奖励统一优先使用 GM 工具配置：

- 经验、天赋点、银币、金币：有 `quest_reward_values` 行则使用这一整行，包括明确设置的 0；没有覆盖行才使用任务原始数值。
- 物品：有 `quest_reward_slots` 行则由这些行决定整套菜单，未配置槽位为空；没有物品覆盖行才使用原始菜单。
- 经验鉴定加成在选定 GM 或原始基础经验后计算。
- 实际发放仅接受最终奖励菜单中的物品，不把原始奖励并入 GM 覆盖菜单。
- 每日、重复任务的每次交付使用独立物品领奖身份，同次交付的重复通知不重复发奖；一次性任务保留终身去重。

GM 覆盖由现有启动流程读取，修改配置在服务端重启后生效。
新增迁移 `20261007_231_quest_reward_completion_claims` 扩展物品领奖去重主键，供新的每日领奖流程使用。

服务端保留客户端原始 `UIQuestSort`、`Color` 等字段。此修改实现服务端分类和接取规则，没有改写客户端 XML 的任务页签分类。
