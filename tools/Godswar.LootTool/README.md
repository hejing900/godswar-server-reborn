# Godswar GM 工具（Godswar.LootTool）

Windows 桌面程序（WinForms），直连 PostgreSQL，四个页签：

| 页签 | 干什么 |
| --- | --- |
| **利兰丁农场** | 农场积分台账（捐卵/击杀/个人分/阵营分）、发放与删除忠犬卵和网兜、清空重置、只读规则常量与已发布 NPC 名册 |
| **怪物掉落表** | 编辑数据库拥有的怪物掉落表：`monster_loot_tables`（表头）+ `monster_loot_rules`（规则），结构照 `tools/verify_monster_loot_migration.sql` 对齐 |
| **任务奖励** | 覆盖某个任务的奖励物品（8 个槽位）与交付数值（经验/TP/银币/金币）：`quest_reward_slots` + `quest_reward_values` |
| **宠物档位** | 宠物种族档位上下限、已有宠物改档、16 档区间发布新版本 |

---

## 编译成 EXE

```powershell
cd D:\Godswar-Reborn-main\tools\Godswar.LootTool
.\publish-loot-tool.ps1
```

产出 **`dist\Godswar.LootTool.exe`** —— **单文件、自包含**（约 50 MB），目标机器**不需要安装 .NET**，拷到哪都能双击运行。
脚本会同时复制一份**同一份发布物**叫 **`dist\GM工具.exe`**（同一程序，两个名字，四个页签都在里面；不要就用 `-SkipGmCopy` 关掉）。
脚本会自动把你当前的连接设置（`loot-tool.settings.json`）复制进发布目录，并对这个 EXE 跑一遍 `--selftest` 验证真能连库读写。

| 说明 | 值 |
| --- | --- |
| 目标平台 | `win-x64`（Windows 64 位） |
| 依赖 | 无（自带 .NET 10 + Windows Desktop 运行时） |
| 单文件 | 是（`PublishSingleFile` + 压缩） |
| 裁剪 | 否（WinForms 不能裁剪） |
| 设置文件 | 生成在 **EXE 同目录** `loot-tool.settings.json` |
| 自测报告 | 生成在 **EXE 同目录** `logs\selftest-*.txt` |

想只产出一个小体积 EXE（约 2–5 MB，但目标机器需装 .NET 10 Desktop Runtime）：

```powershell
.\publish-loot-tool.ps1 -Mode runtime
```

命令行参数（`--connection-string` / `--client-root` / `--selftest`）对 EXE 同样有效，也能用 `dist\Godswar.LootTool.exe --help` 查看。

## 启动

```powershell
cd D:\Godswar-Reborn-main\tools\Godswar.LootTool

.\start-loot-tool.ps1                                  # 构建并打开窗口（默认 D:\Godswar Origin）
.\start-loot-tool.ps1 -SelfTest                        # 只跑数据层自测，不开窗口
.\start-loot-tool.ps1 -ClientRoot 'C:\Godswar Origin'  # 换客户端目录
.\start-loot-tool.ps1 -ConnectionString 'Host=127.0.0.1;Port=5432;Database=godswar_local;Username=godswar;Password=godswar_dev_password'
```

也可以直接跑：

```powershell
dotnet run --project tools/Godswar.LootTool -c Release
```

命令行参数（会被记住，写入 `bin/.../loot-tool.settings.json`）：

| 参数 | 说明 |
| --- | --- |
| `--connection-string <串>` | 覆盖数据库连接串 |
| `--client-root <目录>` | 覆盖客户端根目录（用于中文名） |
| `--selftest` | 数据层自测 + 写入回环，不开窗口 |
| `--pet-check` | 只跑宠物数据层**只读**检查，不开窗口（详见「宠物档位」） |

界面里也有「连接串」「客户端目录」两个输入框，改完点「连接 / 刷新」即可，无需重启程序。

**顶部连接区**（按参照工具的做法，分字段填写，不写连接串）：

| 字段 | 默认值 |
| --- | --- |
| 主机 | 127.0.0.1 |
| 端口 | 5432 |
| 数据库 | godswar_local |
| 用户名 | godswar |
| 密码 | godswar_dev_password |

按钮：

1. **连接数据库** —— 用上面填的信息连库，成功后在右侧显示「连接正常」，并自动读取一次。
2. **一键读取数据** —— 重新拉取怪物列表、物品目录、中文名；换库或换客户端目录后点它。
3. **浏览…** —— 选客户端根目录（中文名来源）。

所有字段都会被记住（`bin\...\loot-tool.settings.json`）。

**左侧怪物列表**：

- **`搜索怪物…`** 按钮 —— 弹窗按 **中文名 / 英文名 / template_key** 搜索，见下方「搜索怪物」。
- `显示所有` 按钮、`按怪物名查询 [___] [查询]`（输入即筛选）
- 筛选下拉：**全部 / 能刷出来的怪 / 未配置掉落 / 已配置掉落**
- 列表列：中文名 / 英文名 / `template_key` / 档位 / 区域 / 地图 / **刷怪点** / 掉落状态
  - **刷怪点为 0 时显示红色「0（不会掉落）」** —— 该怪没进入世界内容，配了也不会掉
  - 掉落按 `template_key` 绑定（`monster_templates` 是每个 source 一行，所以按 key 聚合）

### 搜索怪物

点 `搜索怪物…` 打开弹窗：

- 输入中文名 / 英文名 / key 即时筛选（例如输入「间谍」直接找到斯巴达间谍）
- 勾选 `只看会刷出来的怪` 可过滤掉永远不会掉的模板
- 结果按**刷怪点从多到少**排序，会掉的怪排最前
- 双击或点 `选择该怪物` → 主界面自动定位到该怪并载入它的掉落表（若被筛掉会自动恢复筛选）
- 底部提示「匹配 N 条，其中能刷出来 M 条」，刷怪点为红色 = 配了也不会生效

**右侧掉落编辑**：

- **掉落设置**：`启用该掉落表`、`单次最多掉落件数`（= `maximum_drops`）、当前规则数、`确认修改`（保存）
- **批量调整**：
  - `整体调整 [N] 倍` → `应用当前怪`（只改界面上的数值，需再点「确认修改」保存）／`应用所有怪`（**直接写库**，会二次确认）
  - `统一概率 [X] %` → `改当前怪`（只改界面）／`改所有怪`（**直接写库**，会二次确认）
- **规则表格**：`序号(loot_index)` / `物品ID` / `物品`（自动解析中文名）/ `概率%` / `最少` / `最多` / `启用` / `拾取后` / `物品属性` / `属性…`（按钮）
- **按钮**：新增规则、删除选中规则、物品表…、确认修改、重新载入、删除整张表、自检
- 未保存改动有红点提示；**保存后出现橙色提示：必须重启游戏服务器才生效**

### 「拾取后」这一列（`bound_on_pickup`）

同一条掉落规则可以决定**这件东西捡起来之后能不能交易**，与服务端迁移
`20260927_213_monster_loot_bind_on_pickup` 加的 `monster_loot_rules.bound_on_pickup` 一一对应。
它是**三态**下拉，不是复选框：

| 界面选项 | 库里存的 | 拾取后 |
| --- | --- | --- |
| `跟随物品(默认)` | `NULL` | 按物品模板自己的 `BindType` 走 —— 也就是加这一列之前的老行为，一字不变 |
| `可交易` | `false` | 不绑定，可以交易/丢弃给别人 |
| `拾取绑定` | `true` | 绑定到拾取它的那个角色 |

为什么必须用三态：`NULL` 和 `false` 是**两种不同的意思**（"听物品模板的" ≠ "一定可交易"），
所以工具不会把没选过的规则写成 `false`；认不出的取值会直接报错，不做隐式转换。

顺带一提：同一件物品"可交易"和"已绑定"的两个堆叠**不会合并**（服务端按 `bound` 分堆），
所以给某个怪的掉落选「可交易」后，玩家背包里可能多占一格，这是预期行为。

**旧库还没有这一列时**（服务端迁移没跑）：整列在界面上**隐藏**，状态栏与表格上方会写明原因，
保存也不会去写它 —— 不会静默按默认值写。重启一次服务端跑完迁移，
回来点「一键读取数据」，这一列就出现了。

批量调整（`应用当前怪` / `改当前怪` 以及直接写库的 `应用所有怪` / `改所有怪`）
**只动概率，不碰这一列**；要改它就在表格里逐行选，然后「确认修改」。

### 「物品属性」这一列（品质 / 等级 / 附加属性，12 列）

服务端迁移 `20260927_214_reward_item_attributes` 给 `monster_loot_rules` 与
`quest_reward_slots` **各加了同样 12 列**，都允许 `NULL`：

| 列 | 说明 |
| --- | --- |
| `item_quality` / `item_grade` | 这件物品的品质 / 等级 |
| `attribute1` / `attribute_level1` … `attribute5` / `attribute_level5` | 最多 5 条附加属性：属性 id + 该属性的等级 |

`NULL` = 不配置（服务端仍按现状发：品质 1、等级 1、无附加属性）；
配了就把值写进角色背包里**那一件物品实例**的 `character_items` 同名列。

**属性是"这一件物品"的属性，不是物品模板的属性**：同一个物品从任务奖励给和从怪掉落
可以配成两套完全不同的属性，互不影响 —— 因为两份配置分别存在 `quest_reward_slots` 与
`monster_loot_rules` 里，落在不同的物品实例上。

怎么填：表格里每行有一个 **`属性…`** 按钮，弹窗里填

- `品质` / `等级`：`0 = 不配置`（落库 `NULL`），1 起才是配置值；
- 5 行 `属性 + 等级`：属性是**下拉**（显示 `id 中文名（最高 N 级）`），第一项「（不配置）」；
  等级 `0 = 只配 id 不配等级`（落库 `attribute_level` 为 `NULL`，摘要里显示成 `133/-`）；
- 等级上限会跟着属性自动收紧（选中的属性最高几级就只能填到几级）；
- 同一件物品上**同一个属性不能重复**；只填等级不选属性会被拦下；
- `全部清空（不配置）` 一次把 12 列都清成 `NULL`。

表格里的 `物品属性` 列显示摘要，例如 `品质10 等级12 属性:24/5、133/-、90/-`。
保存时这 12 列跟着槽位/规则一起写；批量倍率与统一概率**不碰它们**（和 `bound_on_pickup` 一致）。

**属性名表从哪来**（工具不内置）：

| 用途 | 来源 |
| --- | --- |
| 有哪些属性 id、最高几级 | 优先服务端表 `item_attribute_templates`（`id` / `name_key` / `max_level` / `percent`）；表不在时退回客户端 `Localization\{语言}\Settings\Sys\ItemAppendAttribute.xml`（`ID` + `L1..Ln` 的个数） |
| 属性的中文名 | 客户端 `Localization\{语言}\Text\EquipDescription.dat`（**UTF-16LE**，`标签<Tab>中文`），用 `name_key` 查，例如 `AttackA → 提升物理攻击力I`。**193 条属性在这份客户端里全部有中文名** |

注意属性 **id 0（`AttackA`）是合法属性**（"提升物理攻击力I"），不是"不配置"，
所以弹窗里"不配置"用的是下拉第一项而不是 0。

名表一条都找不到时，弹窗退化成**纯数字输入**：直接填属性 id，
`-1 = 不配置`（同样因为 0 是合法属性），功能不因此卡住。

**旧库还没有这 12 列时**（迁移 214 没跑）：`物品属性` 与 `属性…` 两列一起**隐藏**，
状态栏写明原因；此时配过属性的规则/槽位保存会被直接拦住，不会静默按默认值写。

中文名来源（客户端目录）：

| 对象 | 来源 |
| --- | --- |
| 怪物 | `Localization\zh_cn\Monster\<区域>\Monster.ini`，段名 = `template_key`，取 `Name=`（该文件是 **UTF-16LE**，工具按 BOM 识别） |
| 物品 | `item_templates.name_key` → `Localization\zh_cn\Text\EquipName.dat`（UTF-8，`name_key<Tab>文本`） |

没有客户端目录时不影响使用，只是名称显示英文。

## 保存时会强制校验（服务端启动不变量）

服务端启动时 `MonsterLootContentSnapshot.Validate` 会拒绝下列数据，工具在写入前就拦住：

| 规则 | 说明 |
| --- | --- |
| `maximum_drops` 1–32 | 表头上限 |
| **规则条数 ≥ `maximum_drops`** | 违反会让**服务端启动直接失败** |
| 规则条数 ≥ 1 | 不想掉落就删整张表，不要留空表 |
| `loot_index` 0–31 且不重复 | 同时是掷骰输入与遍历顺序 |
| `chance_basis_points` 1–10000 | 界面按百分比输入，内部存万分之一 |
| 数量 1–255，且 `最多 ≥ 最少` | |
| `item_id` 必须存在于 `item_templates` | 外键；未知物品会在表格里以 ⚠ 标出 |
| `bound_on_pickup` 三态原样落库 | `NULL` 不会被写成 `false`；库里还没这一列时，选了「可交易/拾取绑定」会被拦住并提示先跑迁移 |

保存是**单事务**：先 upsert 表头与规则，再删除界面上已移除的序号。

## 关于「生效」

掉落内容由服务端在**启动时一次性读入内存**（`MonsterLootContentCatalog.Install`，全仓库没有热加载入口），
所以**改完必须重启游戏服务器**。本工具刻意**不碰 Docker**，只做提示；重启请自行执行：

```powershell
docker compose --profile legacy-raw restart server
```

## 自检（`--selftest` / 界面“自检”按钮）

- 连接、读怪物/物品目录、解析中文名的覆盖情况
- 打印现有掉落表全部内容（物品带中文名）
- **写入回环**：挑一个未配置掉落的怪，临时建表 → 读回比对 → 追加规则 → 删除规则 → 验证不变量拦截 → 清理还原
- 结构与一致性检查：规则数 < 上限的表、空表、停用的表/规则、未配置掉落的怪物数量
- **利兰丁农场**：schema 是否存在、**阵营分 = 同阵营个人积分之和**的不变量、
  有分角色都能拿到排名、当前发布的农场 NPC 名册、从服务端源码读回的 16 条规则常量、
  以及两个**演练写入**（加分与发卵，全程在一个回滚事务里，跑完总分与背包不变）
- **任务奖励**：两张覆盖表存在时，拿一个**本库真实存在**的任务（先查角色做过的任务与
  任务-怪物对照表，取不到才退回抓包奖励记录里的新手任务 518/519/520）走一遍
  写入 → 读回 → 全量替换 → 取消数值覆盖 → 校验拦截 → 删除，**测完不留任何行**；
  旧库还没跑迁移（两张表不存在）时整段报「跳过」而不是失败
- **任务目录解析**：客户端目录可用时解析 `Quest.xml` + `Text\Quest\*.dat`，
  报条数 / 阵营分布 / 等级区间，抽查 5 条标题与任务 518（等级 1、斯巴达），
  并确认标题确实来自客户端文本而不是回落值；顺带报附加属性表（`ItemAppendAttribute.xml`
  + `EquipDescription.dat`）的条数与中文名条数；客户端目录不可用时整段报「跳过」
- **物品属性**：掉落与任务奖励两侧各做一遍 `品质10 / 等级12 / 属性 24 等级5、133、90`
  的写入 → 读回 → 还原 `NULL`，并断言缺列时写属性会被拦住；跑完不留行

报告同时写到 `bin\Release\net10.0-windows\logs\selftest-*.txt`。

## 角色与标记点（第一个页签）

左边按角色名查角色（模糊匹配，留空列出全部），列表直接给出它**当前的地图与坐标**；
右边是**标记点**——「地图 + 坐标」的命名存档，后续的刷怪 / 加 NPC 都会以某个标记点为挂载处。

### 左边：查角色

| 列 | 说明 |
| --- | --- |
| ID / 角色名 / 账号 | 来自 `character_base` + `accounts` |
| 职业 | 0 战士 / 1 斗士 / 2 祭司 / 3 法师（取自服务端班级种子） |
| 等级 / 阵营 | `fighter_job_lv`；阵营 0 斯巴达 / 1 雅典 |
| 地图 | `map<服务端地图号> · 中文图名`（图名来自 `map_templates`） |
| 坐标 (X, Z) | 角色**最近一次落库**的位置 |
| 在线 / 最后登录 | `accounts.login_status` / `character_base.LastLogin_time` |

> **坐标精度**：服务端最多**每 2 秒**把位置写一次库
> （`GameClientHandler.PositionPersistInterval`），所以跑动中的角色会有一个身位的偏差；
> 站定时就是准的。要求精确时用右边的「手动坐标」，或者先站定再取。
>
> 另外 `login_status` 在服务端异常退出后可能是过期值，别只靠它判断在线。

### 右边：标记点

| 操作 | 说明 |
| --- | --- |
| 把这个位置存成标记点 | 用左边**选中角色**的地图 + 坐标新建/覆盖同名标记点 |
| 按手动坐标新增/覆盖 | 用「手动坐标」那一行的 地图下拉 + X/Z/朝向 新建/覆盖 |
| 用选中角色位置覆盖 | 只挪位置，保留名字与备注 |
| 改名 / 备注 | 改名字与备注（名字是唯一键，重名会被挡下并提示） |
| 删除 | 删掉这个标记点（会先问一句） |
| 把坐标填到右边手动框 | 把选中角色的地图/坐标填进手动框，方便微调后另存一个点 |

**名字是天然主键**，所以同一个名字再存一次就是覆盖，不会堆出一串重复点。

### 这张表

`gm_waypoints`，由服务端迁移 `20261004_227_gm_waypoints` 建：

```
id / name(唯一) / note / character_name / map_id / pos_x / pos_z / facing
source('character' | 'manual') / created_at / updated_at / updated_by
```

- 它**不改任何运行时内容**，所以改完立即生效，**不需要重启服务端**（和掉落/任务奖励那些
  启动快照表不一样）。
- 位置列拒绝 NaN/Infinity —— 标记点会被原样抄进刷怪包，坐标必须是能用的有限值。
- 旧库还没跑迁移时，这一页会提示「缺少标记点表」，其他页签不受影响；
  `--selftest` 也会把这一节标成「跳过」而不是失败。

### 自检

`--selftest` 会跑一节「角色与标记点」：地图表条数、角色数与地图能否对上，
以及标记点的**新增 → 查列表 → 覆盖坐标 → 改名 → 删除**整条回环。
回环用带时间戳的探针名字，跑完自己删掉，**绝不碰你存的标记点**。

## 刷怪（第二个页签）

挑一个**标记点**（地图 + 坐标）→ 选一个该图**已发布的怪物模板** → 填数量、等级、血量
与攻防等属性 → 生成一组 GM 刷怪点；右下角管理已生成的点与该图的按模板属性覆盖。

### 为什么只能选「该图已发布的模板」

新刷怪点的包体是从**同图同模板的已发布点拷来的**，只改写对象 ID(8)、等级(12)、
血量(20/24)、坐标(28/36)、朝向(40)。44 字节之后的外观数据没有逆向，所以没有已发布样本的
模板根本造不出点 —— 下拉框里只列该图已出现过的模板，服务端也会再挡一次（模板不在该图
已发布集合里就跳过并打日志）。

### 对象 ID

客户端只认 **8000..49999** 这个怪物注册表；40000/42000/43000/44000 已经被美杜莎 /
亚特兰蒂斯 / 温泉关 / 斯巴达新手那几批自制怪占用，NPC 也大量落在 32000 以上。
所以工具固定从 **46000..49999** 里按图分配空闲 ID，避开：该图已发布的怪、该图的 NPC、
以及工具自己已经写过的点。同一图内对象 ID 撞车会让服务端在**首次进图**时报错，所以这层
避让是必须的。

### 等级 / 血量 与 攻防命闪暴 的区别（重要）

| 字段 | 写到哪 | 为什么 |
| --- | --- | --- |
| 等级、当前/最大血量 | **包体** offset 12 / 20 / 24 | 这两个是"每个刷怪点一份"的数据，服务端启动时会校验（0 会被拒收） |
| 物攻、魔攻、物防、魔防、命中、闪避、暴击、暴抗 | **属性覆盖表** `gm_monster_spawn_edits`（逐点） | 这些在服务端是**代码公式**，包体里没有它们；只能靠覆盖表在结算时替换 |

**所有输入框留空 = 不覆盖**（沿用公式/继承值），不是 0。等级留空则继承底稿怪的等级。

### 生效

服务端**只在启动时**读这三张表（和掉落表同一个约定），所以保存之后要
**重启 `godswar-server`** 才看得到 —— 页签顶部一直用橙字提醒。工具不碰 Docker，重启由
操作者自己做。

### 三张表（服务端迁移 `20261004_228_gm_monster_overrides`）

| 表 | 语义 |
| --- | --- |
| `gm_monster_spawns` | 工具新增的点，带完整 10020 包体；`enabled=false` 即不刷 |
| `gm_monster_spawn_edits` | 按 `(map_id, object_id)` 的逐点覆盖：**改已发布点**（位置/等级/血量）或**屏蔽它**（`enabled=false`），也用来放工具新增点的攻防属性 |
| `gm_monster_attributes` | 按 `(map_id, template_key)` 的属性覆盖，对该模板所有怪生效 |

删刷怪点会**连同它的逐点属性覆盖一起删**（同一个事务）：覆盖是按对象 ID 定位的，只删点会
留下孤儿覆盖，将来任何撞上这个 ID 的怪都会莫名继承它的攻防。

### 自检

`--selftest` 的「刷怪」一节会：列出底稿地图与可选模板 → 用真实模板生成 2 个点 →
验列表 → 停用 → 写一次模板属性覆盖 → 全部清理干净并核对数量回到原样。
探针名字带时间戳，不会碰到你配的点。

## 导出/导入（第三个页签）

把工具配过的东西整体存成一份 JSON，或者把一份 JSON 整份写回来。导出的内容包括
**标记点 + GM 刷怪点 + 逐点属性覆盖 + 按模板属性覆盖**。

- 刷怪点的**包体用 base64 一起带走**，所以换机器/换库导入不需要那边先有同样的已发布内容；
  但**模板仍必须在该图已发布**，否则服务端会拒绝那个点（内容侧的不变量，工具绕不过去）。
- 导入按**天然键** upsert（标记点/刷怪点按名字，属性按 `map+object` 或 `map+template`），
  所以同一份文件导两次结果一样（幂等），也不会打乱目标库的自增序列。
- 导入是**整份事务**：任何一行失败就整体回滚，不会留下"导了一半"的库。

`--selftest` 的「导出/导入」一节验证：整体导出的条数与库一致、JSON 往返不丢条目、
包体 base64 完好、同一份文件导两次结果一样，并且只喂一个**探针专用**的小 bundle
（不是整库导出），跑完把探针删干净并核对数量回到原样。

## NPC 对话与客户端补丁（第四个页签）

**为什么必须打客户端补丁**：客户端渲染对话文字用的是它自己的 Lua
（`Localization/en_us/UI/XML/NpcFun/NpcFun.lua` 的 `Set_NpcFun_Text`），那是一个按
**功能号 Type** 分派的 `if/elseif` 链，**没有 `else`** —— 服务端只发数字，发一个没人
处理的号就什么都不显示。所以"自由文本 + 自定义按钮文字"只能在客户端落地，服务端那半
只负责数字（哪一页、哪几个条目）。

### 已经核实过的客户端约定

对着真实文件（`en_us\UI\XML\NpcFun\` 下的 `NpcFun.lua`、`NpcFunFallback.lua`、
`NpcFunTranmit.lua`、`NpcFunFarm.lua`、`UIMAKER.lua`）逐条确认：

| 事实 | 出处 |
| --- | --- |
| 真正生效的是 `UI\XML\NpcFun\NpcFun.lua`（子目录那份） | 两个 `NpcFun.xml` 都 `<XML File="./Localization/en_us/UI/XML/NpcFunLoad.xml">`，后者第 16 行加载子目录那份；父目录那份没有任何加载点 |
| `Set_NpcFun_Text(Type,Index,BtnID,SubID)`：`Type`=功能号、`Index`=**页号**、`SubID`=条目号 | `NpcFun.lua:177`；`NpcFunTranmit.lua:12` 就是 `if Index == 1 then` 套 `if SubID == …` |
| 正文条目的 SubID 约定是 **101** | `NpcFunFallback.lua` 的 `{1,101,TEXT,NF_L0_1005}` |
| 正文画在 `FirstWin_Text1`，按钮画在 `FirstWin_Button<BtnID>` | `UIMAKER.lua:44/57` |
| 一页最多 **12** 个按钮 | `NpcFun_Clear()` 只处理 `FirstWin_Button1..12` |
| `SetText` 可以直接吃**字符串**，不必是 `NF_L0_*` 文本键 | `UIMAKER.lua:44` / `NpcFunTranmit.lua:14` |
| 分派链里 **0..120 只有 85、86 没人用**，且没有任何已发布 NPC 拿它们当 `dialog_index` | 提取常量表 + 查 `npc_dialogue_profiles` |
| 终点页要自己 `NPCFUN:EndMessage(true)`；**正文条目和按钮不能同页**，否则窗口一闪而过 | `NpcFunTranmit.lua:624-628` |

**工具认领 `Type = 85`。**

### 补丁做什么

`ClientNpcPatch.cs` 打三处补丁，**全部幂等、改前先备份**：

1. 写 `Localization\en_us\UI\XML\NpcFun\NpcFunGM.lua` —— 一个
   `NpcFunGMTOOL_SetText`，按 `Index`(页) / `SubID`(条目) 用**字面字符串**调 `SetText`。
2. 在 `NpcFun.lua` 的 `Set_NpcFun_Text` 顶部插入一个认领 85 的分支
   （原来的分派链**一个字都不动**）。
3. 在 `NpcFunLoad.xml` 的 `</UIConfig>` 前登记新脚本（只登记一次）。

备份文件名形如 `NpcFun.lua.gm-backup-20261004-162616`。命令行也能跑（无界面）：

```powershell
.\dist\GM工具.exe --npc-patch "D:\Godswar Origin"
```

### 校验（`NpcDialogueStore.Validate`）

入口页必须存在；按钮槽位 1..12；按钮不能指向不存在的页；按钮必须有文字；
同一槽位不能配两次；**每一页都必须能从入口页走到**（防止配出孤岛页）。
生成补丁时再挡一次：**页号必须全局唯一** —— 客户端只按 `Index` 找内容，两棵对话抢同一
页号会互相覆盖，所以给每棵对话分一段自己的页号区间（例如 `1001-1099`、`1101-1199`）。

### 尚未核实的一件事（明确记下来，没有在代码里假装知道）

**引擎给 `BtnID` 赋什么值、点击按钮回传给服务端的到底是槽位还是别的数** —— 这在 Lua 里
看不到（`AddWindow` 的 BUTTON 分支只设文字和位置），要进游戏点一次才能定论。补丁目前按
"一页内 `SubID` = 槽位 = 位置"生成，并对每个按钮**显式 `SetPosition`**（客户端默认会把
所有按钮叠在 `(25,135)`，不摆位就是一坨）。

### 验证

`--selftest` 的「NPC 对话与客户端补丁」一节：5 种非法配置必须被拒 → 存库读回 →
生成 Lua 的 10 个结构要点 → 只有终点页有 `EndMessage` → 抢占页号必须报错 →
在**临时目录里真实客户端文件的副本**上打补丁（分派只插 1 个分支、原链未动、加载表登记
1 行、第二次跑零改动、只在真改动前备份）。

生成的 Lua 另外用**真 Lua 解释器**（LuaJIT / lupa）`compile` 过：生成的
`NpcFunGM.lua` 与被打过补丁的 `NpcFun.lua` 都通过解析 —— 这一关当场抓出过两处 `end`
配平错误，所以不是形式主义。

### 页签怎么用

左边是对话列表（一棵 = 一个 NPC 的多级窗口），右边三个可编辑表格：**入口页**、**页**（页号 + 正文）、
**按钮**（页号 + 槽位 1-12 + 文字 + 下一页）。选好地图后底部是**放置**：外观模板下拉只列该图已发布
内容用过的模板，点「取标记点坐标」把坐标从标记点带过来，填对象 ID / npc_key，然后「添加/覆盖放置」。
「保存这棵对话」会先跑一遍全部校验再落库；「生成客户端补丁…」会改客户端目录下那 3 个文件（改前备份）。

服务端那半在 `GameClientHandler.GmNpcDialog.cs`：GM NPC 由进图层注入（publish 之前，所以要走完
既有保留ID/越界/重复键检查），`10067` 广告功能页 85，`10069` 的点击由
`10069 → GmNpcDialoguePolicy.TryStep` 查下一步并回 `10070`。线路条目号 = `页号×1000 + 条目`
（正文 +101，按钮 +1..+12），工具与服务端各有一份测试钉住同一组数值。

## 利兰丁农场（第五个页签）

同一个程序里的第五个页签，读写的都是**服务端正在用的那两张积分台账**，所以改完立即对
服务器生效（服务器每次查询都是现查数据库，不需要重启）。

### 数据模型（先看这个，再动手）

| 表 / 视图 | 谁写的 | 说明 |
| --- | --- | --- |
| `lelantine_farm_donations` | 服务端（玩家捐卵）、本工具（GM 调整） | 每笔捐卵流水：`character_id`、`faction`、`item_id`、`egg_count`、`points` |
| `lelantine_farm_kill_points` | 服务端（击杀记分）、本工具 | 击杀个人分，主键 `character_id + faction` |
| `lelantine_farm_personal_points`（视图） | — | **个人积分的唯一定义**：上面两张表按角色+阵营求和 |
| `lelantine_farm_faction_points` | 已删除 | 旧的"只累计捐赠"的阵营总分，与"阵营分=个人分之和"冲突，迁移 `20260926_210` 里删掉了 |

**阵营总分是派生值**：`阵营分 = 该阵营所有个人积分之和`。工具因此**没有**"直接改阵营分"的操作
——改流水就是改阵营分，不会出现第二份会漂移的数字。

### 能做什么

| 子页 | 能做什么 | 写到哪 |
| --- | --- | --- |
| **角色积分总览**（左侧） | 按角色名/ID 查询；看个人积分、捐卵分、击杀分、排名、阵营总分 | 只读 |
| **捐卵流水** | 改选中行分值、删除选中行、给该角色**手动加一笔调整行**（`item_id = 0`，与真实捐卵可区分） | `lelantine_farm_donations` |
| **击杀积分** | 设选中行分值、清零（保留行）、删除该阵营行 | `lelantine_farm_kill_points` |
| **背包农场物品** | 看角色背包里的忠犬卵/网兜（含资质）；**发放**忠犬卵（资质 1/5/8 任选）与各档网兜；删除选中堆 / 删除该物品全部堆 | `character_items` + 一行 `character_item_audit`（`source='gm-tool'`） |
| **清空/重置** | 清空某角色全部农场积分；清空某阵营全部农场积分（会连带清掉该阵营所有角色的个人分） | 两张流水表 |
| **只读：规则常量** | 显示 16 条规则常量（三档卵分值、1~99 上限、击杀 1/10/1000、10 级门槛、广播阈值与类型/频道等），**值是从服务端源码文件里读出来的**，不是工具里的副本 | 只读 |
| **只读：已发布 NPC** | 当前发布版本（`npc_content_publication` 头版本）下地图 42 的农场 NPC 名册与坐标 | 只读 |

### 使用注意（重要）

1. **目标角色在线时不要改背包**：服务器内存里有该角色的背包状态，下次存档会覆盖发放。
   改积分台账不受影响（服务器每次现查），但**发卵/删卵要求角色离线**。
2. **删除是永久的**：流水行删掉就没有了，阵营分与个人分同时下降；工具不会自动备份。
3. **资质决定分值**：忠犬卵的 `item_quality` 就是宠物资质，只有 **1（懦弱）=1 分、
   5（理智）=10 分、8（热情）=100 分** 三档计分，其它资质捐了会被服务端拒绝。
   用本工具发卵时选对资质即可。
4. **背包满时发放会被拒绝**（96 格全占），工具会明确报错且不写任何数据。
5. 单次捐卵 **>100 分** 会触发服务端的世界广播（屏幕中间黄字），这是服务端行为，
   工具不参与；广播阈值在"只读：规则常量"里能看到。

## 任务奖励（第七个页签）

同一个程序里的第七个页签（在「怪物掉落表」之后），读写的是服务端迁移
`20260927_212_quest_reward_overrides` 建的两张表：

| 表 | 一行是什么 | 没有该任务的行 |
| --- | --- | --- |
| `quest_reward_slots` | 该任务奖励菜单的第 `slot_index`（0-7）个槽位放哪个 `item_id` | 沿用服务端内置的抓包奖励 |
| `quest_reward_values` | 该任务交付时付的经验 / TP / 银币 / 金币 | 沿用服务端内置数值 |

**两条语义必须记住**（界面右下角也写着）：

1. `quest_reward_slots` 里**只要该任务有一行**，这个任务的奖励菜单就**完全**由这些行决定
   —— 没写的槽位就是空的，不是「部分覆盖」。所以保存是**整份替换**：先 `DELETE` 该任务的
   全部槽位再插入勾选的那些，而不是逐槽补写。
2. `quest_reward_values` 有行 = 覆盖那四个数值；没有 = 沿用内置。
   **取消勾选「覆盖数值」并保存 = 删掉该行**，任务回到内置数值。

工具**不显示内置奖励内容**：内置的槽位与数值来自服务端抓包的奖励记录，工具里没有副本，
所以未覆盖的任务显示为「未覆盖（沿用内置）」，不会猜一个数字出来。

### 界面怎么用

左侧「任务列表」：

- `搜索任务`：把**客户端任务表里的全部任务**读进列表（几千条，解析一次就缓存住）。
  数据源就是顶部「客户端目录」指向的那份客户端，工具不内置任何任务副本：
  - `Localization\{语言}\Settings\Sys\Quest.xml` —— 提供 `ID`、`MinLevel`、`Faction`
    （**0 = 斯巴达，1 = 雅典**）、发布/交付 NPC。该文件是 **UTF-8（带 BOM）**；
    `ID="0"` 的占位行会被跳过（任务 ID 必须 > 0）。
  - `Localization\{语言}\Text\Quest\{id}.dat` —— 每个任务的标题，形如 `{[Lv3] 木头人}`，
    取自 `Title` 关键字后的大括号（大括号内外空格都容忍）。该文件是 **UTF-16LE（带 BOM）**；
    文件缺失或没有标题段时回落成 `Lv{MinLevel} 任务{id}`。
  - 语言目录默认 `zh_cn`，先从客户端里探测（`zh_cn` → `en_us` → 第一个存在的目录）。
    找不到客户端/文件时列表上方会直接把**期望路径**报出来。
- 列表列：`任务ID` / `等级+名字`（就是上面的标题，例如 `[Lv3] 木头人`）/ `阵营`（斯巴达/雅典/未标注）/ `覆盖状态`。
- 过滤：`按名字/ID 过滤 [____]`（名字与 ID 都匹配，输入即筛选）+ `阵营 [全部/斯巴达/雅典]` 下拉，
  两个条件可以叠加（例如只看斯巴达里名字含「佛卡」的任务）。
- `刷新` 只重新拉一次库里的覆盖状态，不会重读客户端任务表（换客户端请点「搜索任务」）。
- 没有搜索过客户端时，列表退回「库里已覆盖的任务 + 手填的 ID」，不会假装知道任务名。
- `任务 ID [____] [载入]`：填任意 quest id 回车或点「载入」即可编辑，**手填的 ID 也能保存**
  （即使客户端任务表里没有它）；库里没有覆盖的任务显示成红色「未覆盖（沿用内置）」。

右侧「奖励物品」：

- 固定 8 行槽位表：`槽位 0-7` / `物品ID` / `物品名`（自动解析客户端中文名）/ `启用` / `物品属性` / `属性…`（按钮）。
  勾选 = 该槽有奖励，未勾选 = 该槽为空（界面上的物品 ID 会留着方便再勾回来，但不写库）。
- **`属性…`**：给这一件奖励物品配品质/等级/附加属性（同一个弹窗，语义见上一节的
  「物品属性」这一列）—— 任务给的这一件和怪掉的同一件物品**各配各的**。
- `浏览…` 打开物品表（`ItemPickerForm`，可搜 ID / 中文名 / 英文名 / name_key）选物品，
  选完自动勾上「启用」；也可以直接在 `物品ID` 列手打 ID。
- `重新载入该任务` = 丢掉界面改动、按库里的内容重画。
- `清空该任务覆盖` = 删掉两张表里该任务的所有行（回到内置奖励），会二次确认。
- `保存` = 一个事务里写完两张表。

右侧「奖励数值」：`覆盖数值` 勾选框 + 经验 / TP（天赋点）/ 银币 / 金币四个整数框；
不勾时四个框是灰的（表示这里不是内置值的位置，工具不知道内置值）。

保存前会拦下这些错误（都在写库之前）：quest_id ≤ 0、槽位不在 0-7、勾了启用却没选物品、
`item_id` 不存在于 `item_templates`、数值为负或不是整数；物品属性那边则是
属性等级超过该属性上限、只填等级不选属性、同一属性重复。

**保存成功后出现橙色提示：必须重启游戏服务器才生效** —— 和掉落表一样，
服务端只在启动时读一次（`QuestRewardContentCatalog.Install`），工具不碰 Docker：

```powershell
docker compose --profile legacy-raw restart server
```

旧库还没跑迁移时（两张表不存在），页签只显示一句
「数据库 X 缺少任务奖励表（quest_reward_slots / quest_reward_values），请先启动一次游戏服务端让它跑迁移…」，
不读也不写，其余页签照常可用。

## 宠物档位（第八个页签）

同一个程序里的第八个页签，读的是**所连数据库自己**的宠物内容表（换库就跟到哪个库）。三个子页：

| 子页 | 能做什么 | 写到哪 |
| --- | --- | --- |
| **种族档位上下限** | 给 46 个种族各设「最低档 / 最高档」；`把上下限随机写进背包里的蛋` 按钮按区间重写蛋实例的 `item_quality`（可留空角色名 = 全部角色） | 新表 `public.gm_pet_species_aptitude_bounds`（**服务端不读这张表**，它是 GM 侧的策略记录）+ `character_items.item_quality` |
| **已有宠物（改档位）** | 选一只已有宠物，直接改成 1–16 任意档 | `character_pets` 的 `aptitude` / `talent_mask` / `has_owner_merge_talent` / `birth_rank` / `hatch_rank_outcome_order` / `revision` + 一行 `pet_operation_audit`（`operation = 'gm_tool_set_aptitude'`） |
| **16 档区间（可发布新版本）** | 直接编辑每档的「成长率下/上限、出生资质下/上限、附加值下/上限」，点「发布为新版本」 | 新建一个 revision（见下）并把 `pet_content_publication` 指过去 |

### 为什么改 16 档区间要"发布新版本"

`pet_content_aptitude_definitions` 等 6 张内容表上有 `reject_pet_content_mutation()` 触发器，
**任何 UPDATE/DELETE 都会被数据库直接拒绝**（published content 不可变，这是服务端启动不变量）。
所以工具做的是唯一被允许的路径：

1. 读 `pet_content_publication`（family=`pets`）拿到当前发布版本；
2. 用新 revision id（对改动内容取 SHA-256，大写 64 位十六进制，符合
   `ck_pet_content_revisions_revision`）插一行 `pet_content_revisions`，**声明计数与旧版本一致**；
3. 把 16 档按界面上的新数值插进新版本（`innate_talent_mask` 由规则重算，界面上不可编辑），
   其余 11 张内容表原样复制（`pet_content_magic_jade_appearance_groups` 是视图，不复制）；
4. `INSERT ... ON CONFLICT (family) DO UPDATE` 把发布指针指过去 ——
   `validate_pet_content_publication()` 触发器会核对每一张表的行数，不完整就报错回滚，
   通过则自动 `sealed_at = now()` 封存新版本。

**旧版本整份留在库里**，`character_pets` 指向旧 revision 的外键因此不会断。
服务端只在启动时读内容，所以**发布后必须重启服务器才生效**。

无窗口回环自测（在一份拷贝库上跑，不动正式库）：

```powershell
docker exec godswar-postgres psql -U godswar -d postgres -c "CREATE DATABASE pet_publish_test TEMPLATE godswar;"
.\bin\Release\net10.0-windows\Godswar.LootTool.exe --connection-string "Host=127.0.0.1;Port=5432;Database=pet_publish_test;Username=godswar;Password=godswar_dev_password" --pet-check publish
```

`--pet-check publish` = 只读检查 + 用**相同数值**走一遍发布回环，验证新版本被接受、指针切换、读回一致；测完 `DROP DATABASE pet_publish_test` 即可。

为什么改已有宠物要顺带动那几个字段（都是数据库自己的约束，不是工具自作主张）：

- `ck_character_pets_quality_innate_talents` 强制 `talent_mask = CASE aptitude >= 14 → 31, >= 10 → 26, else 0`，所以**档位和天赋掩码必须一起写**；
- `ck_character_pets_merge_talent_projection` 强制 `has_owner_merge_talent =` 掩码的第 16 位；
- 外键 `fk_character_pets_hatch_rank_evidence` 要求 `(孵化内容版本, aptitude, outcome_order, birth_rank)` 在 `pet_content_hatch_rank_steps` 里存在，所以改档时 `birth_rank` 会跟着换成新档那一行的值。

**六维资质、附加值、成长率一律不动**（这是刻意选的：改档只改档，老宠不会突然变强或变弱）。
孵化时服务器读的是**蛋实例的 `item_quality`**（`PostgresPetDurableCommandExecutor.BagActivation.cs` 把它直接当 aptitude 用），所以「以后的宠物按上下限出」是靠改蛋实现的，不需要动服务端代码。

档位名有两套，界面同时显示：项目语义名（`docs/pet-system-foundation.md` 有意重排了 6–10）和客户端实际画出来的名字（`Localization\zh_cn\UI\Base\text.lua` 的 `PETAPTITUDE1..16`）。**两者在 6–10 档就是错开的**：数值 7 服务端叫「暴躁 Grumpy」，客户端显示「聪慧型」。所以客户端显示"聪慧型"却没有天赋，不是掩码丢了，而是那一档按服务端规则本来就没天赋（门槛是数值 ≥ 10）。本工具只报告这个不一致（第三个子页会标出来），不擅自改名或改门槛。

无窗口版检查：

```powershell
.\bin\Release\net10.0-windows\Godswar.LootTool.exe --pet-check
```

打印 16 档 / 46 种族 / 现有宠物的完整读数，校验掩码规则一致性，并确认 1–16 每档都有孵化 rank（即**每一档都真的能被写入**）。**全程只读，不改任何游戏数据。**

## 说明

- 目标框架 `net10.0-windows`（Windows 专用）。**故意不加入 `GodswarServer.sln`**，以免破坏 Linux/Docker 的解决方案构建。
- 依赖仅 `Npgsql 10.0.2`（与其它工具一致），无额外 UI 依赖。
- 默认连接串取自仓库根 `appsettings.json` 的 `storage.postgresConnectionString` 的主机/端口/账号，
  但**库名改成本地服务端实际在用的 `godswar_local`**。
- 掉落是**按 `template_key` 绑定**：同一个 key 出现在多张地图时共享同一张掉落表。想按地图区分，只能用不同的 key。
